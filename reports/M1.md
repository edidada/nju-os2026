# NJU OS 2026 M1 迷宫实验报告

基线为官方 Git 的 M1 分支 f122b35cd8ee03e71cf19f980505c83a31cdde07。官方题面：https://jyywiki.cn/OS/2026/labs/M1.md 。本仓库为官方 Git 镜像；实验分支 edidada/M1，不是社区答案导入。

实现参数校验、矩形地图解析、100×100 边界、有效字符和重复玩家检查。遍历把玩家视为空地，显式栈 DFS 保证连通性，避免递归深度风险。移动时先验证方向和目标，缺失玩家以首个空地作为起点；失败不改地图。写入同目录临时文件，全部写入成功再 rename，避免失败覆盖原文件；读取命令原样输出原始字节。

命令行支持长短参数任意顺序，缺失/重复/未知选项和非法 player 返回1。version 必须单独使用。原 tests.c、testkit 源文件保留。独立 M1.yml 直接 GCC 编译并执行全部公开 TestKit，再核查通过数等于总数；没有运行课程自动提交脚本，也没有向 OJ 提交，因此公开测试通过不能代表私有 OJ 验收。

官方 oslab.mk 的默认目标会生成追踪提交，CI 直接调用 GCC，避免测试过程修改 Git 历史。实现由 AI 自动化完成，用于个人自学；不把它申报为学生独立完成或校内成绩。本地未编译。

补充黑盒验证覆盖恰好100×100、超长行/超高地图、空输入、坏字符、重复玩家、无末尾换行、失败不改文件，并以 Python 独立状态机核对500次种子固定的实际进程移动。

首次原样公开测试为18/22：四个成功路径系统测试失败。定位发现 tests.c 的 SystemTest 参数数组包含 ./labyrinth，而当前 TestKit 又自动前置 argv[0]，使 main 收到重复的可执行文件参数。CI 生成 tests_compat.c，仅去掉数组中重复的 ./labyrinth；保留所有用例、参数、断言和原文件，不在产品参数解析中容忍无关参数。另以独立 Python 子进程黑盒验证真实命令行行为。该兼容步骤明确公开，不能称为上游源码原样全通过。
